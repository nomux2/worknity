# フロントエンド開発ルール (Frontend Rules)

React SPA (TypeScript) および CSS を用いたフロントエンド開発における、型安全性、パフォーマンス、優れたUX（楽観的UI・デザイン原則）を担保するためのルールを定義します。

---

## 1. TypeScript による厳格な型安全性の徹底
* **ルールの要旨**: 暗黙的な `any` の使用を完全に禁止し、実行時エラーを最小化する。
* **具体的アクション**:
  1. `tsconfig.json` の `strict` モードを有効化し、`any` を使用しない。必要な場合は `unknown` を用い、適切に型ガード（Type Guard）を行う。
  2. APIレスポンスやリクエストボディの型は、バックエンドのスキーマと同期させ、一貫したインターフェース定義を `types/` ディレクトリ等に集約する。
  3. `as` による強制的キャストは極力避け、適切な初期値設定やオプショナルチェイニング（`?.`）を活用する。

## 2. 楽観的UI（Optimistic UI）の一貫した実装
* **ルールの要旨**: ユーザーへの「即時操作性」を提供しつつ、通信エラー時の整合性を担保する。
* **具体的アクション**:
  1. 在庫の入出庫や棚卸など、レスポンスを待たずにUIを先行更新（Optimistic Update）する際は、**必ずリクエスト失敗時のロールバック（巻き戻し）処理をペアで実装する**こと。
  2. 画面の先行更新中に再度別の操作が発生した場合の競合を防ぐため、リクエスト中は一時的に更新対象の行やボタンにローディング表示または入力制限をかけ、多重送信を防ぐ。
  3. エラーが発生した場合は、トースト通知等でエラー内容をユーザーに明確に伝え、元の正しい状態に画面表示を安全に戻す。

## 3. JWT認証およびセッションの安全な管理
* **ルールの要旨**: フロントエンドでの認証情報の漏洩（XSS等による奪取）を防ぐ。
* **具体的アクション**:
  1. ログイン成功時に取得した JWTトークンは、**`localStorage` や `sessionStorage` には保存しない**。React のメモリ（State や Context）上でのみ保持する。
  2. 画面リロード（F5）やタブを閉じた後の再アクセスに対応するため、セキュアCookie（`HttpOnly`, `Secure`, `SameSite=Lax/Strict`）を用いたサイレントトークンリフレッシュ（または自動ログイン処理）をバックエンドと連携して実装する。

## 4. Vanilla CSSによるデザインシステムとUX原則
* **ルールの要旨**: TailwindCSSなどのフレームワークを安易に使わず、美しくプレミアムなデザインをVanilla CSSで制御する。
* **具体的アクション**:
  1. スタイリングには **Vanilla CSS** を使用し、デザインシステム（色、フォント、余白、影など）を `src/index.css` に CSS変数（Custom Properties）として定義する。
  2. デフォルトのブラウザフォントは使用せず、Google Fonts等から curated されたプレミアムなフォント（Inter, Outfit 等）を指定する。
  3. ホバーエフェクト、フォーカス状態、モーダルのフェードイン・フェードアウトなどには、なめらかなイージングをかけた **トランジション・アニメーション（Micro-animations）** を必ず適用する。
  4. すべての主要コンポーネントは、モバイル（スマートフォン）とデスクトップ（PC）の双方で認知負荷なく操作できるよう、レスポンスデザイン（Media Queries）を徹底する。

## 5. UIプレースホルダー・アセットの扱い
* **ルールの要旨**: 開発中の仮の表示であっても、安易な仮置きテキストや空白の画像エリアを放置しない。
* **具体的アクション**:
  1. 画像が必要な場合はプレースホルダー画像URLを直書きせず、`generate_image` ツールなどで作成したアセットを使用するか、CSSグラデーション等で美しく代替する。
  2. スケルトンスクリーンや適切なローディング表示（Shimmer効果など）を実装し、データ取得中のガタツキ（Layout Shift）を防ぐ。
