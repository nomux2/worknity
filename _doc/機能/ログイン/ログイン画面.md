# 画面設計書：ログイン・新規登録画面

本書は、ミニマリスト業務統合サービス「Worknity（フェーズ1）」における「ログイン・新規登録画面」のレイアウト, UI要素, 画面遷移, およびインタラクション仕様を定義する。

ソーシャルログイン（Google, LINE, Microsoft, Yahoo! JAPAN）、パスキー（生体認証）、および従来のパスワード認証を美しく統合し、ユーザーに「圧倒的な簡単さ」と「高いセキュリティ�## 2. UIレイアウト（ワイヤーフレーム）

ボタンの乱立による「選択疲れ（認知負荷）」を防ぐため、スマートフォンの所持率や利用シーンを考慮し、主要な2つのプラットフォーム（Google, LINE）を大きく配置し、ビジネス/日本国内で補助的に使われる2つ（Microsoft, Yahoo! JAPAN）をその下にコンパクトな横並びで配置する。

また、IT苦手層や初めてのユーザーの心理的ハードルを下げるための「初心者向けサポート機能」は、既存ユーザーのノイズにならないよう、メインのログインカードの外側（下部）に配置する。

## 4. 画面仕様・インタラクション（新体験フロー）

### 4.1. ソーシャルログイン/登録フロー（最速：ワンタップ）
1. ユーザーがいずれかのソーシャルログインボタン（Google / LINE / Microsoft / Yahoo! JAPAN）を押す。
2. バックエンドへリダイレクトし、各プラットフォームの認証画面を表示。
3. 認証成功後、バックエンドは連携されたメールアドレスを取得。
   * **既存ユーザーの場合：** 即座にJWTを発行し、メインの在庫管理画面へ遷移。
   * **新規ユーザーの場合：**
     * 自動的に `companies`（企業レコード）と `users`（ロール: admin）を作成。
     * フロントエンド側で「ウェルカム！会社名（屋号）を入力してください」という1つの入力欄を持つモーダルをオーバーレイ表示。
     * 入力して保存すると、そのまま業務を開始できる。

### 4.2. パスキー（顔・指紋認証）フロー（メール ＋ ワンタップ）
1. ユーザーが「メールアドレス」を入力。
2. `[ パスキーでサインイン ]` ボタンを押す。
3. ブラウザ標準の生体認証（Windows Hello / Face ID / Touch ID）のポップアップが起動。
4. **認証成功時：** パスワード入力なしで即座にログインが完了し、在庫管理画面へ遷移。
5. **認証資格情報がない場合：** 「このデバイスにはパスキーが登録されていません。」とエラー案内を表示。

### 4.3. 従来のパスワードログインフロー（フォールバック）
1. ユーザーが「メールアドレス」と「パスワード」を入力。
2. `[ パスワードでログイン ]` ボタンを押す。
3. バックエンドでパスワードハッシュを検証し、成功すればログイン。

### 4.4. 対話型登録ウィザードフロー（初心者向け）
1. ユーザーがログインカード外の `[ 🔰 やさしく登録する ]` をクリック。
2. 画面が対話型ウィザードUI（またはモーダル）に切り替わり、1画面1ステップで以下の情報を入力・設定させる。
   * **ステップ1：組織（店舗）名の登録**
     * 「まずは、あなたのお店や会社のお名前を教えてください！」と優しく案内。
     * 入力欄に組織名（屋号など）を入力し、`[ 次へ ]` ボタンを押す。
   * **ステップ2：メールアドレスの登録と検証**
     * 「ありがとうございます！次に、ログインで使うメールアドレスを教えてください。」と案内。
     * メールアドレスを入力し、`[ 確認コードを送信 ]` を押すと、バックエンドからワンタイム確認コードが送信される。
     * 画面上のコード入力欄で認証完了すると次のステップへ。
   * **ステップ3：パスキー（生体認証）の設定**
     * 「最後に、次回から1秒でログインできるよう、このデバイスの指紋や顔認証（パスキー）を設定しましょう（後からでも設定可能です）。」と案内。
     * **安全性の補足説明を表示**：
       * パスキー設定ボタンのすぐ下に、「💡 **パスキーが安全な理由：** あなたの指紋や顔のデータはデバイス内だけで安全に保護され、Worknityのサーバーには送信されません。パスワードのように漏洩したり、推測されて不正アクセスされたりする心配がない最新の安全な仕組みです。」という説明を常時表示する。
     * `[ パスキーを設定する（推奨） ]` または `[ パスワードを設定して完了する ]` のいずれかを選択。
3. 登録完了後、バックエンドに組織およびユーザー（ロール: admin）データが自動作成され、メインの在庫管理画面へ遷移。

### 4.5. 登録不要の「10秒デモ」フロー（お試し体験）
1. ユーザーがログインカード外の `[ 🔍 10秒デモを試す ]` をクリック。
2. **体験テンプレート（業種）の選択モーダル表示**：
   * 画面中央に、体験したい業種（機能パッケージ）を選択するシンプルなモーダルを表示する。
     * **🏪 店舗・小売向けデモ**
       * 初期表示：**在庫管理画面**
       * ダミーデータ：商品の在庫、入出庫履歴、売上日報など
     * **🏥 介護・福祉向けデモ**
       * 初期表示：**ホーム（申し送り・お知らせ）画面** または **顧客管理（利用者カルテ）**
       * ダミーデータ：本日の申し送り事項、利用者の対応記録など
     * **🏢 一般オフィス向けデモ**
       * 初期表示：**プロジェクト管理（タスク）画面**
       * ダミーデータ：プロジェクトの進捗、タスクカンバンなど
3. **デモ画面への遷移**：
   * 選択された業種に応じて、ダミーデータが初期投入された状態でデモ画面（例：`https://app.worknity.jp/demo?template=care`）へリダイレクト。
4. **データ管理仕様**：
   * デモ画面での各種操作（入出庫・タスク更新・申し送り追加など）は、サーバーには一切送信せず、フロントエンド側（`sessionStorage`）のみで擬似的に処理する。これにより、リロードしてもデータが維持されつつ、インフラへの負荷とセキュリティリスクを完全にゼロに抑える。
5. **本登録（データの引き継ぎ）への導線**：
   * デモ画面の上部には、「現在デモ体験中です（データは保存されません）。気に入ったら、このデータを引き継いで正式登録できます！」というバナーを常時表示する。
   * バナー内の `[ データを引き継いで正式登録（無料） ]` ボタンを押すと、デモ期間中に作成・変更したデモデータを一時保持したまま、上記の「4.4. 対話型登録ウィザードフロー」へ遷移する。
   * ウィザードによる本登録完了時に、一時保持していたデモデータをバックエンドに一括同期し、即座に本番運用を開始できる。

## 5. 新規登録（サインアップ）時のパスキー登録体験
メールアドレスとパスワードで**新規にアカウントを作成した直後**、システムはユーザーに以下の新体験ポップアップを提示する。

> 💡 **次回からパスワード不要でログインしませんか？**
>
> このデバイスの顔認証や指紋認証（パスキー）を登録すると、次回からパスワードの入力なしで安全に1秒ログインできます。
>
> 🔒 **パスキーが安全な理由**
> * **生体データは送信されません**：指紋や顔の情報はデバイス内だけで安全に保護され、サーバーやネットワーク上に送信・保存されることはありません。
> * **パスワード不要で漏洩ゼロ**：パスワードを使わないため、ハッキングや使い回しによる不正アクセスの危険性をゼロに抑えられます。
>
> `[ パスキーを登録する（推奨） ]`   `[ あとで ]`

* ユーザーが `[ パスキーを登録する ]` を選ぶと、ブラウザの鍵登録API（WebAuthn）が走り、その場で生体情報をデバイスに紐づける。これにより、次回からの面倒な入力を完全に排除する。|

| 7 | **パスワード入力欄** | パスワード入力 | 空 | - | `type="password"`。目のアイコンで表示/非表示切り替え可能。 |
| 8 | **パスワードログインボタン** | ボタン | `パスワードでログイン` | - | メールアドレスとパスワードを入力してログインを実行。 |
