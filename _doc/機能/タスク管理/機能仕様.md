# タスク管理 機能仕様書

本書は、ミニマリスト業務統合サービス「Worknity」におけるタスク管理機能、繰り返し生成機能、コメント（申し送り）管理機能のビジネスルール、権限、および詳細な仕様を定義するものである。

---

## 1. 機能概要

タスク管理機能は、日々の業務、店舗のルーティンワーク、または特定のプロジェクトに紐づくタスクを登録・追跡・完了するための機能である。
また、繰り返し発生する定常業務を自動化する「繰り返し生成機能」と、日々の申し送りを見逃さないための「タスクコメント・クリーンアップ機能」を提供する。

---

## 2. アクターと権限

* **管理者 (`admin`)**:
  - 通常タスクおよび繰り返しルールの作成、編集、削除。
  - すべてのタスクコメントの閲覧、投稿、および「古いコメントの一括削除（クリーンアップ）」。
* **一般スタッフ (`staff`)**:
  - タスク一覧の閲覧、自身が担当するタスクのステータス更新・工数入力。
  - タスクコメントの閲覧、自身のコメントの投稿・編集・削除。
  - （繰り返しルールの編集・一括削除機能は利用できない）。

---

## 3. ユースケースと詳細仕様

### 3.1. タスク一覧の閲覧（仮想マッピング）
* **説明：** ログインユーザーは、自組織のタスクをリスト形式またはカンバン形式で閲覧できる。
* **仕様：**
  - プロジェクトに所属しない「日常の単発タスク/ルーティン」と、特定のプロジェクトに紐づくタスクを並行して管理できる。
  - **仮想マッピング**: 繰り返しタスク（実レコードは1つ）は、カレンダー画面やスケジュール画面上において、繰り返しルールに従って毎日・毎週などの発生日に動的にマッピング表示される。

### 3.2. タスクの登録・編集
* **入力項目：**
  - タスク名（必須）
  - 概要説明（任意）
  - 担当者ユーザーID（任意）
  - プロジェクトID（任意・Null許容）
  - 期限日（任意）
  - 予定工数・実績工数（任意）
  - 繰り返しルール設定（任意）

### 3.3. 繰り返しタスク生成と非稼働日シフトロジック
繰り返しルールを設定したタスクは、カレンダーへのマッピングおよび自動生成（日次のステータスリセット）の際、以下のロジックに従って「稼働日」を判定する。

* **繰り返しパターン**:
  - `daily` (毎日), `weekly` (毎週), `biweekly` (隔週), `monthly` (毎月), `first_day_of_month` (月初), `last_day_of_month` (月末)
* **稼働曜日・休日の判定データ**:
  - 組織設定に保持された「稼働曜日（月〜日）」と、`calendar_holidays` テーブルに登録された「組織休日（祝日・独自休日）」を参照する。
* **非稼働日と重複した場合のシフト挙動**:
  繰り返し予定日が非稼働日（休日）と重なった場合、ルールで指定された以下のいずれかの処理を行う。
  1. **そのまま生成 (`as_is`)**: 非稼働日であってもその日に予定をマッピング/生成する。
  2. **翌稼働日にシフト (`next_working_day`)**: 直後の最も近い稼働日（営業日）に日付を移動する。
  3. **前稼働日にシフト (`prev_working_day`)**: 直前の最も近い稼働日（営業日）に日付を移動する。
  4. **スキップ (`skip`)**: その回のタスク表示・生成を行わない。

### 3.4. コメント・申し送り機能（属性付き）
各タスクに対して、作業中の連絡や申し送りを記録できるコメント機能を提供する。

* **コメントの属性**:
  コメント投稿時に、以下のメタデータを付与できる。
  1. **重要度 (`importance`)**: `high` (高) / `medium` (中) / `low` (低)
  2. **種類 (`type`)**: `communication` (連絡) / `handover` (申し送り) / `log` (作業ログ) / `memo` (メモ)
  3. **関連タスク (`related_task_id`)**: 他のタスクIDを指定して、タスク間の依存関係や関連性を紐付け可能。
* **表示仕様**:
  - 繰り返しタスクは単一レコードであるため、カレンダー上のどの日の予定からタスク詳細を開いても、過去に書き込まれたすべてのコメント履歴が時系列で表示される（「来週やります」等の過去コメントがそのまま確認可能）。

### 3.5. 古いコメントの一括削除（クリーンアップ）
コメントの累積によるデータ肥大化やノイズ化を防ぐため、管理者は条件を指定してコメントを一括削除できる。

* **一括削除の条件（フィルタ）**:
  以下の条件を組み合わせて削除対象を絞り込む。
  - **期間指定**: 「指定日以前」または「現在からX日前以前（例: 30日前、90日前など）」。
  - **種類指定**: 削除するコメントの種類（例: 「メモ」と「作業ログ」のみ削除し、「申し送り」は残す）。
  - **重要度指定**: 削除するコメントの重要度（例: 「低」と「中」のみ削除し、「高」は残す）。

---

## 4. ビジネスルールとバリデーション

### 4.1. 入力バリデーションルール
1. **タスク名：**
   - 必須入力。最大100文字。
2. **工数（予定工数・実績工数）：**
   - 0以上の半角整数（または小数点第1位までの数値）のみ許容。
3. **繰り返し設定：**
   - パターンを指定した場合は、非稼働日シフト設定（`as_is` / `next_working_day` / `prev_working_day` / `skip`）も必須とする。

---

## 5. セキュリティとデータガード設計

1. **他テナント存在の隠蔽 (404 Not Found)：**
   - タスク詳細（`GET /api/v1/tasks/{id}`）やコメント操作において、指定されたタスクが他組織（`organization_id` が異なる）のデータである場合は、一律 **`404 Not Found`** を返却する。

2. **コメント一括削除の安全性ガード：**
   - 一括削除処理を実行する際、クエリの `WHERE` 条件に必ず `organization_id` を含める。
   - 例: `DELETE FROM task_comments WHERE organization_id = ? AND created_at < ? AND type IN (?)`
   - これにより、バグや不正なパラメータ送信によって他テナントのコメントが誤って削除されることをデータベース物理レベルで完全に防止する。
