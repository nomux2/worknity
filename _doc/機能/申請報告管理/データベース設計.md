# 申請報告管理 データベース設計書

本ドキュメントは、「申請/報告」機能（申請報告管理）に必要なテーブル構造, インデックス, およびマルチテナント設計について定義します。

---

## 1. データベース設計 of 基本方針

1. **マルチテナント隔離 (`organization_id` の徹底)**
   * すべてのテーブルに `organization_id` を配置し、全てのクエリでテナント分離が行われるよう設計します。
   * テナント間でのクエリ漏れ防止およびパフォーマンス向上のため、テナント依存の全テーブルで `organization_id` を先頭に配置した複合インデックスを必ず設定します。
2. **JSON型カラムの活用 (`attributes`, `fields`)**
   * バックエンドの物理カラムを動的に追加せず、ユーザーが自由に変更できる入力欄は `reports.attributes` (JSON) で吸収します。
   * テンプレートの入力項目定義は `report_templates.fields` (JSON) に定義します。
3. **共通ワークフローエンジン化（ポリモーフィック関連の活用）**
   * 発注管理（`orders`）や勤怠申請（`attendance_requests`）など、システム全体の多様なモデルからの承認依頼に相乗りできるよう、`reports` テーブルにポリモーフィック関連カラム（`approvable_type`, `approvable_id`）を配置します。
3. **トランザクションと悲観的ロック**
   * 承認・却下時や次のステップへの移行など、ステータス変更を伴う更新処理は、多重送信による不整合を防ぐため、`DB::transaction()` 内で対象の `reports` レコードを `lockForUpdate()` (悲観的ロック) して取得・更新します。
4. **承認者クラスマスタの導入**
   * 承認ルート設定やユーザーの承認権限を動的に変更可能にするため、固定の役職名ではなく、テナントごとに自由に役職を登録できる `approval_classes` テーブルおよびユーザーとの紐付けテーブルを導入します。

---

## 2. テーブル一覧

| 物理テーブル名 | 論理テーブル名 | 説明 |
| :--- | :--- | :--- |
| `approval_classes` | 承認者クラス | テナントごとに定義される承認用の役職マスタ（例: 「部長」「先生」など）。 |
| `user_approval_classes` | ユーザー承認者クラス紐付け | 各ユーザーに対して承認者クラス（役職）をマッピングする中間テーブル。 |
| `report_templates` | 申請報告テンプレート | 申請/報告の入力フォームやフローの定義を保持するマスタ。 |
| `report_approval_routes` | 承認ルート定義 | テンプレートごとの承認ステップ（担当クラスやユーザー）の定義。 |
| `reports` | 申請報告データ | ユーザーが作成・提出した実際の申請/報告データ。入力値は JSON で保持。 |
| `report_approvals` | 承認・却下履歴 | 各ステップの承認および却下の履歴（コメントを含む）。 |

---

## 3. テーブル詳細設計

### 3.1. `approval_classes` テーブル (承認者クラス)

* **説明：** 組織独自の承認用の役職（例：「副部長」「部長」「先生」「経理」など）を管理するマスタ。

#### カラム定義
| No | 物理名 | 論理名 | 型 | 長さ | Null | Key | デフォルト | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `id` | クラスID | BIGINT | 20 | NO | PK | - | 自動採番 (Unsigned) |
| 2 | `organization_id` | 所属組織ID | BIGINT | 20 | NO | FK | - | `organizations.id` への外部キー |
| 3 | `name` | クラス名 | VARCHAR | 100 | NO | - | - | 例:「部長」「先生」「経理」 |
| 4 | `priority` | 優先度 (序列) | INT | 11 | NO | - | 10 | 役職の上下関係（数値が大きいほど上位役職） |
| 5 | `created_at` | 作成日時 | TIMESTAMP | - | YES | - | NULL | - |
| 6 | `updated_at` | 更新日時 | TIMESTAMP | - | YES | - | NULL | - |

#### インデックス・制約
* **外部キー：**
  * `fk_approval_classes_org` : `organization_id` ➡ `organizations(id)`
* **インデックス：**
  * `idx_approval_classes_org` : `(organization_id)`

---

### 3.2. `user_approval_classes` テーブル (ユーザー承認者クラス紐付け)

* **説明：** ユーザーに特定の承認者クラス（役職）を割り当てる中間テーブル。

#### カラム定義
| No | 物理名 | 論理名 | 型 | 長さ | Null | Key | デフォルト | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `id` | ID | BIGINT | 20 | NO | PK | - | 自動採番 |
| 2 | `organization_id` | 所属組織ID | BIGINT | 20 | NO | FK | - | `organizations.id` への外部キー |
| 3 | `user_id` | ユーザーID | BIGINT | 20 | NO | FK | - | `users.id` への外部キー |
| 4 | `approval_class_id` | 承認者クラスID | BIGINT | 20 | NO | FK | - | `approval_classes.id` への外部キー |
| 5 | `created_at` | 作成日時 | TIMESTAMP | - | YES | - | NULL | - |
| 6 | `updated_at` | 更新日時 | TIMESTAMP | - | YES | - | NULL | - |

#### インデックス・制約
* **外部キー：**
  * `fk_user_app_classes_org` : `organization_id` ➡ `organizations(id)`
  * `fk_user_app_classes_user` : `user_id` ➡ `users(id)` (ON DELETE CASCADE)
  * `fk_user_app_classes_class` : `approval_class_id` ➡ `approval_classes(id)` (ON DELETE CASCADE)
* **一意制約（Unique）：**
  * `uk_user_app_class` : `(organization_id, user_id, approval_class_id)` (重複割り当て防止)
* **インデックス：**
  * `idx_user_app_classes_org_user` : `(organization_id, user_id)` (ログインユーザーの権限判定用)

### 3.3. `report_templates` テーブル (申請報告テンプレート)

* **説明：** 組織ごとに作成される申請/報告のフォームの定義。

#### カラム定義
| No | 物理名 | 論理名 | 型 | 長さ | Null | Key | デフォルト | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `id` | テンプレートID | BIGINT | 20 | NO | PK | - | 自動採番 (Unsigned) |
| 2 | `organization_id` | 所属組織ID | BIGINT | 20 | NO | FK | - | `organizations.id` への外部キー |
| 3 | `name` | テンプレート名 | VARCHAR | 100 | NO | - | - | 例:「旅費精算」「日報」 |
| 4 | `description` | 説明文 | TEXT | - | YES | - | NULL | テンプレートの使用方法などのガイド |
| 5 | `type` | テンプレート種別 | VARCHAR | 50 | NO | - | 'report' | 'report' (報告/日報), 'application' (申請/稟議) |
| 6 | `steps_count` | 承認ステップ数 | INT | 11 | NO | - | 1 | 承認フローの総ステップ数 (1〜3) |
| 7 | `fields` | 入力項目定義 | JSON | - | NO | - | - | フォーム項目スキーマ (配列オブジェクト) |

| 9 | `updated_at` | 更新日時 | TIMESTAMP | - | YES | - | NULL | - |

#### インデックス・制約
* **外部キー：**
  * `fk_report_templates_org` : `organization_id` ➡ `organizations(id)`
* **インデックス：**
  * `idx_report_templates_org_type` : `(organization_id, type)`

### 3.4. `report_approval_routes` テーブル (承認ルート定義)

* **説明：** テンプレートごとの承認ステップ設定。承認者として「特定の個人」または「特定の承認者クラス（役職）」のいずれかを指定します。

#### カラム定義
| No | 物理名 | 論理名 | 型 | 長さ | Null | Key | デフォルト | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `id` | ルートID | BIGINT | 20 | NO | PK | - | 自動採番 |
| 2 | `organization_id` | 所属組織ID | BIGINT | 20 | NO | FK | - | `organizations.id` への外部キー |
| 3 | `report_template_id` | テンプレートID | BIGINT | 20 | NO | FK | - | `report_templates.id` への外部キー |
| 4 | `step_number` | ステップ番号 | INT | 11 | NO | - | - | 承認順序 (1〜3) |
| 5 | `approver_type` | 承認者指定タイプ | VARCHAR | 50 | NO | - | 'class' | 'class' (承認者クラス指定), 'user' (特定ユーザー指定) |
| 6 | `approval_class_id` | 承認者クラスID | BIGINT | 20 | YES | FK | NULL | `approval_classes.id` への外部キー |
| 7 | `approver_user_id` | 承認ユーザーID | BIGINT | 20 | YES | FK | NULL | `users.id` への外部キー (個人指定用) |
| 8 | `created_at` | 作成日時 | TIMESTAMP | - | YES | - | NULL | - |
| 9 | `updated_at` | 更新日時 | TIMESTAMP | - | YES | - | NULL | - |

#### インデックス・制約
* **外部キー：**
  * `fk_routes_org` : `organization_id` ➡ `organizations(id)`
  * `fk_routes_template` : `report_template_id` ➡ `report_templates(id)` (ON DELETE CASCADE)
  * `fk_routes_class` : `approval_class_id` ➡ `approval_classes(id)` (ON DELETE SET NULL)
  * `fk_routes_user` : `approver_user_id` ➡ `users(id)`
* **一意制約（Unique）：**
  * `uk_routes_step` : `(organization_id, report_template_id, step_number)`
* **インデックス：**
  * `idx_routes_org_template` : `(organization_id, report_template_id)`

### 3.5. `reports` テーブル (申請報告データ)

* **説明：** ユーザーが提出した申請/報告の実際のデータ。入力値は動的なJSONで管理。

#### カラム定義
| No | 物理名 | 論理名 | 型 | 長さ | Null | Key | デフォルト | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `id` | データID | BIGINT | 20 | NO | PK | - | 自動採番 |
| 2 | `organization_id` | 所属組織ID | BIGINT | 20 | NO | FK | - | `organizations.id` への外部キー |
| 3 | `report_template_id` | テンプレートID | BIGINT | 20 | NO | FK | - | `report_templates.id` への外部キー |
| 4 | `user_id` | 作成ユーザーID | BIGINT | 20 | NO | FK | - | `users.id` への外部キー（申請・報告者） |
| 5 | `status` | ステータス | VARCHAR | 50 | NO | - | 'draft' | 'draft', 'pending', 'awaiting_input', 'approved', 'rejected' |
| 6 | `current_step` | 現在のステップ | INT | 11 | NO | - | 1 | 現在承認待ち/入力待ちのステップ番号 |
| 7 | `attributes` | 入力値データ | JSON | - | NO | - | - | 画面項目の入力値 (キー・値ペアのJSON) |
| 8 | `approvable_type` | 被承認連携モデル | VARCHAR | 100 | YES | - | NULL | ポリモーフィック連携モデル名 (例: `App\Models\Order`) |
| 9 | `approvable_id` | 被承認連携データID | BIGINT | 20 | YES | - | NULL | ポリモーフィック連携データID (例: `orders.id` の値) |
| 10 | `created_at` | 作成日時 | TIMESTAMP | - | YES | - | NULL | 提出・保存日時 |
| 11 | `updated_at` | 更新日時 | TIMESTAMP | - | YES | - | NULL | 最終更新日時 |

#### インデックス・制約
* **外部キー：**
  * `fk_reports_org` : `organization_id` ➡ `organizations(id)`
  * `fk_reports_template` : `report_template_id` ➡ `report_templates(id)`
  * `fk_reports_user` : `user_id` ➡ `users(id)`
* **インデックス：**
  * `idx_reports_org_user` : `(organization_id, user_id, status)`
  * `idx_reports_org_status` : `(organization_id, status, current_step)`
  * `idx_reports_approvable` : `(organization_id, approvable_type, approvable_id)` (被承認データからの逆引き検索用)

### 3.6. `report_approvals` テーブル (承認・却下履歴)

* **説明：** 承認・却下の履歴とコメントを保持。

#### カラム定義
| No | 物理名 | 論理名 | 型 | 長さ | Null | Key | デフォルト | 説明 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | `id` | 履歴ID | BIGINT | 20 | NO | PK | - | 自動採番 |
| 2 | `organization_id` | 所属組織ID | BIGINT | 20 | NO | FK | - | `organizations.id` への外部キー |
| 3 | `report_id` | 申請データID | BIGINT | 20 | NO | FK | - | `reports.id` ➡ 申請データへの外部キー |
| 4 | `step_number` | 対象ステップ番号 | INT | 11 | NO | - | - | 承認・却下対象のステップ番号 |
| 5 | `user_id` | 処理ユーザーID | BIGINT | 20 | NO | FK | - | `users.id` ➡ 処理を行った承認者のID |
| 6 | `action` | アクション | VARCHAR | 50 | NO | - | - | 'approved' (承認), 'rejected' (却下) |
| 7 | `comment` | コメント | TEXT | - | YES | - | NULL | 承認時の申し送りや、却下理由 |
| 8 | `created_at` | 処理日時 | TIMESTAMP | - | YES | - | NULL | 承認・却下日時 |
| 9 | `updated_at` | 更新日時 | TIMESTAMP | - | YES | - | NULL | - |

#### インデックス・制約
* **外部キー：**
  * `fk_approvals_org` : `organization_id` ➡ `organizations(id)`
  * `fk_approvals_report` : `report_id` ➡ `reports(id)` (ON DELETE CASCADE)
  * `fk_approvals_user` : `user_id` ➡ `users(id)`
* **インデックス：**
  * `idx_approvals_org_report` : `(organization_id, report_id)`
