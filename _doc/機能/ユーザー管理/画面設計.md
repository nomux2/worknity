# ユーザー管理 画面設計書

本書は、ミニマリスト業務統合サービス「Worknity」におけるユーザー管理（スタッフ一覧・編集・追加）の画面レイアウト、UI要素、および操作インタラクションについて定義するものである。

---

## 1. 画面概要

* **画面名：** ユーザー管理（スタッフ一覧・設定）画面
* **アクセスURL：** `https://app.worknity.jp/users`
* **アクセス制限：**
  * ロールが `admin` (管理者) のユーザーのみアクセス可能。
  * `staff` (スタッフ) ロールのユーザーがこのURLにアクセスした場合は、ホーム画面へリダイレクトし、トーストで「アクセス権限がありません」と警告を表示する。
* **目的：** 
  * 組織に所属するスタッフの把握
  * 新規スタッフアカウントの追加作成
  * 既存スタッフの権限変更・アカウント状態（有効/一時停止）の切り替え
  * 退職等に伴うスタッフの組織からの削除（所属解除）

## 2. UIレイアウト（ワイヤーフレーム）

### 2.1. スタッフ一覧画面
画面上部に「スタッフを追加」ボタンを配置し、メイン領域にテーブル形式で所属メンバーを表示する。

```text
+------------------------------------------------------------------------------------------+
|                                                                                          |
|  👥 スタッフ管理                                                   [ + 新しいスタッフを追加 ]  |
|                                                                                          |
|  +------------------------------------------------------------------------------------+  |
|  | メールアドレス / ログインID     | 権限ロール    | アカウント状態 | 登録日     | 操作       |  |
|  +-------------------------------+---------------+---------------+------------+------------+  |
|  | admin@example.com             | [ 管理者  ▼ ] | ( ◯ 有効 )    | 2026/06/01 | [ 非活性 ] |  | <-- 最後の管理者（操作不可）
|  +-------------------------------+---------------+---------------+------------+------------+  |
|  | staff_tanaka@example.com      | [ スタッフ▼ ] | [ ● 有効   ]  | 2026/06/02 | [ 削除 ]   |  | <-- 一般スタッフ

|  +-------------------------------+---------------+---------------+------------+------------+  |
|                                                                                          |
+------------------------------------------------------------------------------------------+
```

## 3. UI要素一覧（コンポーネント仕様）

### 3.1. メイン画面の要素
| No | 要素名 | 種別 | 初期値 / 表示テキスト | 必須 | 仕様・制約 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | **新しいスタッフを追加ボタン** | ボタン | `+ 新しいスタッフを追加` | - | クリック時に「スタッフ追加モーダル」をオーバーレイ起動。 |
| 2 | **権限ロール選択プルダウン** | セレクトボックス | 現在のロール | **必須** | `admin` または `staff` を選択。変更時に即時API送信。※最後の管理者行では非活性化。 |
| 3 | **アカウント状態トグル** | スイッチ / ボタン | 現在の状態 | **必須** | 有効（緑）/ 一時停止（グレー）をトグル切替。※最後の管理者行では非活性化。 |
| 4 | **削除ボタン** | ボタン | `削除` | - | クリック時に「所属解除の確認ダイアログ」を表示。※最後の管理者行では非活性化。 |

### 3.2. 追加モーダルの要素
| No | 要素名 | 種別 | 初期値 / 表示テキスト | 必須 | 仕様・制約 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 5 | **メールアドレス入力欄** | テキスト入力 | 空 | **必須** | `type="email"`。システム全体で未登録のメールアドレスであること。 |
| 6 | **パスワード入力欄** | パスワード入力 | 空 | **必須** | `type="password"`。8文字以上。目のアイコンで表示/非表示切り替え。 |

## 4. 画面仕様・インタラクション

### 4.1. 状態切り替え（楽観的UI更新：Optimistic UI）
ユーザー管理テーブル内の「アカウント状態トグル」を操作した際、以下の流れで状態を更新する。

1. 管理者がトグルスイッチをクリックする。
2. フロントエンドは**APIのレスポンスを待たずに**、トグルの表示を即座に「有効 ➡ 一時停止」（または逆）に切り替える。
3. 裏側でバックエンドAPI（`PUT /users/{id}`）に状態変更リクエストを送信。
4. **API送信が成功した場合：** そのまま状態を確定する（トースト等で「状態を変更しました」と小さく通知）。
5. **API送信が失敗した場合（通信エラーやバリデーション却下）：** 
   - トグルの表示を操作前の元の状態に「スッと」戻す。
   - 画面上部に赤色のトーストで「変更に失敗しました。時間をおいて再度お試しください（エラー理由）」と表示する。

### 4.2. 最後の管理者の保護表示（セルフロックアウト防止）
システムは、組織内の「有効な管理者」が1人しか存在しない状態を検知すると、その管理者自身の行の操作インターフェースを非活性化する。

* **表現：** 該当行の「権限ロールプルダウン」「アカウント状態トグル」「削除ボタン」をグレーアウト（`disabled`）にする。
* **ツールチップ表示：** グレーアウトされた要素にマウスホバーまたはタップした際、以下のメッセージをツールチップで表示する。
  > ⚠️ 組織内にアクティブな管理者が少なくとも1人存在する必要があります。

### 4.3. 所属解除（削除）のアラート警告
スタッフの削除（`DELETE /users/{id}`）は取り消しができない重大な操作であるため、二段階の確認フロー（ダイアログ）を挟む。

1. `削除` ボタンを押すと、画面中央に警告ダイアログが出現。
   > ⚠️ **スタッフの所属を解除しますか？**
   >
   > この操作により、該当スタッフ（`{メールアドレス}`）は組織のデータにアクセスできなくなります。
   > 過去の履歴データ（在庫操作ログなど）は引き続き保持されます。
   >
   > `[ 本当に削除する ]`    `[ キャンセル ]`
2. `[ 本当に削除する ]` をクリックした場合のみ、APIリクエストを投げてテーブルから行をアニメーション（フェードアウト）を伴って消去する。
