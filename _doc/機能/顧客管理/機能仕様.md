# 顧客管理 機能仕様書

本書は、ミニマリスト業務統合サービス「Worknity」における顧客管理機能のビジネスルール、システム要件、および詳細な仕様を定義するものである。

---

## 1. 機能概要

顧客管理機能は、サービス業（介護、美容院、ネイルサロン等）における一般顧客情報を一元的に記録・管理する機能である。  
各テナント（店舗・企業）の業態に応じた柔軟な情報管理を可能とするため、**「標準項目（物理列）の表示/非表示制御」**および**「ユーザーが定義するカスタム項目（JSON列）の追加」**をサポートし、登録されたすべての項目を指定した詳細検索（絞り込み検索）を提供する。

---

## 2. アクターと権限

本機能は、顧客情報の登録・検索という日常業務（スタッフ）と、管理用の項目設定（管理者）に分かれており、役割に応じて操作範囲を制限する。

* **管理者（`admin`）**：
  * 顧客情報の閲覧、新規登録、編集、削除
  * 顧客カスタム項目定義（ビルトイン項目の有効/無効化、カスタム項目の作成・編集・削除）
* **一般スタッフ（`staff`）**：
  * 顧客情報の閲覧、新規登録、編集（※削除は管理者のみ、または権限制限を推奨）
  * 顧客カスタム項目定義の閲覧のみ（設定変更は不可）

---

## 3. ユースケースと詳細仕様

### 3.1. 顧客一覧と絞り込み検索（メイン画面）
* **一覧表示**：
  * 自テナントの顧客一覧を、フリガナ（`kana`）の五十音順で表示する。
  * リストには、顧客名、フリガナ、および有効化されている代表的な項目（電話番号など）を表示する。
* **絞り込み検索（詳細検索）**：
  * **基本項目検索**：名前（部分一致）、フリガナ（部分一致）に加え、有効化されている「電話番号」「メールアドレス」「住所」で個別に絞り込み検索が行える。
  * **カスタム項目検索**：管理者によって「検索対象（`is_searchable`）」として定義されたカスタム項目（JSON列内の値）について、入力形式に応じた個別の検索窓（部分一致、完全一致、範囲指定等）を提供し、混同のない正確な絞り込みを実現する。
    * 例：住所で「愛知県」かつ、カスタム項目の備考で「静岡出身」と検索した場合、正しくアンド条件で絞り込まれ、住所に「静岡」が含まれるだけの顧客は除外される。

### 3.2. 顧客情報の登録・編集
* **動的フォームレンダリング**：
  * 登録・編集フォームは、項目設定（`customer_fields`）を元に動的に生成される。
  * `is_enabled` が `true` の項目のみが表示され、無効化された標準項目（例：郵便番号や住所）は画面上に表示されない。
* **項目の保存先切り分け（パターンB）**：
  * **標準項目**（名前、フリガナ、電話番号、Email、郵便番号、住所）は、`customers` テーブルの対応する**物理カラム**に保存する。
  * **カスタム項目**（管理者が任意で追加した項目）は、`customers.attributes` の **JSON型カラム**内に `{ "key": "value" }` の形式で保存する。

### 3.3. 顧客カスタム項目定義（管理者設定画面）
管理者専用の「管理 ＞ 顧客カスタム項目設定」画面から、入力項目を定義する。

* **標準項目の有効/無効設定**：
  * フリガナ、電話番号、メールアドレス、郵便番号、住所について、「画面に表示する（有効）」かどうかのチェックボックスを設ける。（※名前は必須項目のため無効化不可）
* **カスタム項目の新規追加・編集・削除**：
  * **項目キー（`field_key`）**：半角英数字（例：`care_level`, `hair_type`）。
  * **表示名（`field_name`）**：画面上のラベル（例：`介護度`, `髪質`）。
  * **入力形式（`field_type`）**：以下の4種類から選択。
    1. `text` (テキスト入力)
    2. `number` (数値入力)
    3. `select` (選択式 - 選択肢をJSON配列で管理)
    4. `date` (日付入力)
  * **検索対象フラグ（`is_searchable`）**：ONの場合、顧客一覧画面の検索条件エリアに対象項目の入力欄が追加される。
  * **表示順序（`sort_order`）**：フォーム内での表示位置を調整するための数値。

## 4. ビジネスルールとデータ整合性（バックエンド）

### 4.1. マルチテナントの隔離とデータガード
* `customers` および `customer_fields` テーブルに対するすべての操作は、Laravel Eloquent のグローバルスコープにより、現在ログインしているユーザーの `organization_id`（テナント）に紐づくデータに自動で絞り込まれる。
* 他テナントの顧客IDや項目IDがリクエストに含まれていた場合は、漏洩・推測を防ぐため **`404 Not Found`** を返却する。

### 4.2. 動的バリデーションの強制
* 顧客の登録・更新API（`CustomerController`）は、テナントごとに定義された `customer_fields` のメタデータを取得し、動的にバリデーションルールを生成して検証する。
  * 例：項目定義で `field_type = 'number'` に設定されている場合、送信された値が整数値であることをバリデータで確認する。
  * 例：項目定義で `field_type = 'date'` に設定されている場合、正しい日付フォーマット（`YYYY-MM-DD`）であることを確認する。

---

## 5. UI/UX設計（フロントエンド）

### 5.1. 動的フォームコンポーネントの共通化
* 定義マスタから取得した項目配列をループ処理し、それぞれの `field_type` に適したUIコンポーネント（`<Input>`、`<Select>`、`<DatePicker>` 等）を動的に切り替えて描画する。
* 未入力状態でもレイアウトシフト（ガタツキ）が発生しないよう、スケルトンスクリーンや適切な高さ確保を行う。

### 5.2. プレミアムな動作設計
* 顧客リストの選択切り替え時や、詳細検索エリアの展開/格納時には、Vanilla CSS によるスムーズなトランジション（イージング）を適用する。
* 保存完了時にはトースト通知を表示し、登録された顧客が即座に一覧リストの適切な位置（五十音順）に表示されるよう、状態（State）を制御する。
