# 発注管理 データベース設計書

本ドキュメントは、発注管理機能で必要となるテーブル構造、インデックス、および在庫管理などの他モジュールとの連携に伴うスキーマ拡張について定義します。

---

## 1. データベース設計の基本方針

1. **マルチテナント隔離 (`organization_id` の徹底)**
   * 発注に関するすべてのテーブルに `organization_id` を配置し、全てのクエリでテナント分離が行われるよう設計します。
   * テナント間でのクエリ漏れ防止およびパフォーマンス向上のため、`organization_id` を先頭に配置した複合インデックスを設定します。
2. **整合性と悲観的ロック**
   * 入荷登録（`stocks.quantity` の加算および `order_items.received_quantity` の更新）は、二重更新による不整合（レースコンディション）を防ぐため、`DB::transaction()` 内で `lockForUpdate()` (悲観的ロック) を用いて実行します。
3. **外部モジュールとのリレーション**
   * 共通ワークフローエンジン（[申請報告管理機能](file:///home/ubuntu/worknity/_doc/機能/申請報告管理/機能仕様.md)）側のポリモーフィック関連によって、発注データ（`orders`）と申請データ（`reports`）が紐付きます。
   * 取引先情報は既存の `partners` テーブルとリレーションを持ちます。
   * 在庫反映および履歴追跡のため、既存の `stock_logs` テーブルに `order_id`（NULL許容）を追加します。

---

## 2. テーブル一覧

| 物理テーブル名 | 論理テーブル名 | 説明 |
| :--- | :--- | :--- |
| `order_settings` | 発注設定 | テナントごとに発注時の承認要否設定や金額のしきい値、使用する申請テンプレートを保持します。 |
| `orders` | 発注 | 発注伝票のヘッダー情報（発注先、ステータス、担当者など）を管理します。 |
| `order_items` | 発注明細 | 発注する商品、数量、単価、入荷済みの数量などを管理します。 |

---

## 3. テーブル定義詳細

### 3.1. `order_settings`（発注設定テーブル）

組織ごとに、発注処理時の承認フロー要否およびしきい値、連動する申請テンプレートを管理します。

| カラム名 | 物理名 | 型 | NULL | 初期値 | キー | 説明 |
| :--- | :--- | :--- | :---: | :---: | :---: | :--- |
| 設定ID | `id` | bigint | NO | | PK | 自動採番 |
| 組織ID | `organization_id` | bigint | NO | | FK, UK | 所属組織ID (`organizations.id`) |
| 承認必須フラグ | `require_approval` | tinyint(1) | NO | 0 | | 1: 発注時に承認を必須とする, 0: 承認不要 |
| 承認しきい値 | `approval_threshold` | int | YES | NULL | | 承認が必要な発注合計金額の最小値（これ未満は自動承認、NULLなら金額不問で require_approval に従う） |
| 申請テンプレートID | `report_template_id` | bigint | YES | NULL | FK | 連動する申請テンプレートID (`report_templates.id` ON DELETE SET NULL) |
| 作成日時 | `created_at` | timestamp | NO | | | |
| 更新日時 | `updated_at` | timestamp | NO | | | |

#### インデックス・制約定義
* **Primary Key**: `id`
* **Unique Key**: `(organization_id)` （1組織1設定）
* **Foreign Key**:
  * `organization_id` ➡ `organizations(id)`
  * `report_template_id` ➡ `report_templates(id)` ON DELETE SET NULL

---

### 3.2. `orders`（発注テーブル）

発注伝票の基本情報を保持します。

| カラム名 | 物理名 | 型 | NULL | 初期値 | キー | 説明 |
| :--- | :--- | :--- | :---: | :---: | :---: | :--- |
| 発注ID | `id` | bigint | NO | | PK | 自動採番 |
| 組織ID | `organization_id` | bigint | NO | | FK | 所属組織ID (`organizations.id`) |
| 取引先ID | `partner_id` | bigint | NO | | FK | 発注先取引先ID (`partners.id`) |
| 発注番号 | `order_number` | varchar(50) | NO | | UK | 組織内でユニークな発注識別番号 (例: PO-YYYYMMDD-XXXX) |
| 発注日 | `order_date` | date | NO | | | 発注を行った日付 |
| 希望納期 | `delivery_deadline` | date | YES | NULL | | 納品を希望する日付 |
| ステータス | `status` | varchar(30) | NO | 'draft' | | `draft` (下書き), `pending_approval` (承認待ち), `ordered` (発注済), `partially_received` (一部入荷済), `completed` (入荷完了), `cancelled` (キャンセル) |
| 担当者ID | `created_by` | bigint | NO | | FK | 発注担当のユーザーID (`users.id`) |
| 作成日時 | `created_at` | timestamp | NO | | | |
| 更新日時 | `updated_at` | timestamp | NO | | | |

#### インデックス・制約定義
* **Primary Key**: `id`
* **Unique Key**: `(organization_id, order_number)` （テナント内で発注番号が重複しないように制御）
* **Foreign Key**:
  * `organization_id` ➡ `organizations(id)`
  * `partner_id` ➡ `partners(id)`
  * `created_by` ➡ `users(id)`
* **複合インデックス**:
  * `idx_org_status` : `(organization_id, status)` (ステータス検索の高速化)
  * `idx_org_order_date` : `(organization_id, order_date)` (日付順ソート・検索用)
  * `idx_org_partner` : `(organization_id, partner_id)` (取引先別検索用)

---

### 3.3. `order_items`（発注明細テーブル）

発注された商品（在庫アイテム）ごとの明細行を保持します。

| カラム名 | 物理名 | 型 | NULL | 初期値 | キー | 説明 |
| :--- | :--- | :--- | :---: | :---: | :---: | :--- |
| 明細ID | `id` | bigint | NO | | PK | 自動採番 |
| 組織ID | `organization_id` | bigint | NO | | FK | 所属組織ID (`organizations.id`) |
| 発注ID | `order_id` | bigint | NO | | FK | 属する発注ID (`orders.id` ON DELETE CASCADE) |
| 在庫ID | `stock_id` | bigint | NO | | FK | 発注対象の在庫ID (`stocks.id`) |
| 発注数量 | `quantity` | int | NO | | | 発注する合計数量 |
| 入荷済数量 | `received_quantity` | int | NO | 0 | | 既に納品・入荷が完了した数量（分納管理用） |
| 発注単価 | `unit_price` | int | NO | | | 発注時の単価（消費税等は考慮しない本体価格） |
| 作成日時 | `created_at` | timestamp | NO | | | |
| 更新日時 | `updated_at` | timestamp | NO | | | |

#### インデックス・制約定義
* **Primary Key**: `id`
* **Foreign Key**:
  * `organization_id` ➡ `organizations(id)`
  * `order_id` ➡ `orders(id)` ON DELETE CASCADE
  * `stock_id` ➡ `stocks(id)`
* **複合インデックス**:
  * `idx_org_order` : `(organization_id, order_id)`
  * `idx_org_stock` : `(organization_id, stock_id)` (商品別発注中数量の集計高速化用)

## 4. 既存テーブルのスキーマ拡張

### 4.1. `stock_logs`（在庫変動履歴ログ）
入荷処理が行われた際に、どの発注伝票に基づく入荷履歴かを追跡可能にするため、以下のカラムを追加します。

* **追加カラム**:
  * `order_id` (bigint, NULL可, FK ➡ `orders(id)` ON DELETE SET NULL)
* **用途**:
  * 履歴タイムライン上で、その在庫の増加がどの「発注番号（注文書）」によるものかを紐付けて表示するために使用します。
