# 画面設計書：ホーム画面（在庫管理）

本書は、ミニマリスト業務管理システム「Worknity（フェーズ1）」における「ホーム画面（在庫管理ダッシュボード）」の仕様を定義する。

---

## 1. 私たちが目指す「シンプル」の定義

「シンプル」とは、単に「機能を削ること」ではありません。私たちは、ユーザーが**「考えずに、一目で状況を理解でき、迷わず次にすべき操作を行えること」**をシンプルと定義します。

具体的には、以下の3つの原則を徹底します。

1. **認知的シンプル（一瞥で伝わる）：**
   数字の羅列を頭の中で計算させない。グラフやビジュアルを用いて「今、アクションを起こすべきか（発注が必要かなど）」が1秒で視覚的に伝わるようにする。
2. **操作的シンプル（思考と行動の直結）：**
   「見つける ➔ 操作する」の間にページ遷移や複雑なドロップダウンを挟まない。すべての主要アクションは、ホーム画面の1タップ・1キー入力から開始できる。
3. **技術的シンプル（隠された高度さ）：**
   表向きは極限までスマートに見せるが、裏では悲観的ロックによる多重更新防止や、将来のAI連携（MCP）などの高度な仕組みが完璧に機能している。

## 2. UIレイアウト（ワイヤーフレーム）

### 2.1. メインダッシュボードレイアウト
全体状況を瞬時に把握できる「在庫ステータスバー」と、各商品の直近の動きがわかる「ミニ・トレンドグラフ（スパークライン）」を導入し、シンプルさと情報の伝わりやすさを両立させます。

```text
+-------------------------------------------------------------------------+
| [Worknity]   ワークニティ流通 (管理者)                 [設定] [ログアウト] |
+-------------------------------------------------------------------------+
|                                                                         |
|  📊 在庫の健康状態                                                      |
|  +-------------------------------------------------------------------+  |
|  | [■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■□□□□□□■■■] |  | <-- 1本でわかる全体ステータス
|  |  (良好: 80% / ⚠️警告: 15% / ❌不足: 5%)                            |  |
|  +-------------------------------------------------------------------+  |
|                                                                         |
|  [ 🔍 商品名で検索...                  ]        [ + 新しい商品を登録 ]  |
|                                                                         |
|  +-------------------------------------------------------------------+  |
|  | 商品名             | 数量 | 7日間の動き (グラフ) | 状態   | 操作  |  |
|  +--------------------+------+---------------------+--------+--------+  |
|  | ミネラルウォーター |  120 | 📈 ( ~\_/\_/\_ )    | 良好   | [操作] |  | <-- トレンド表示
|  | オフィス用紙 A4    |   15 | 📉 ( \_\_\_/\_\\ )    | ⚠️警告  | [操作] |  | <-- 状態バッジ
|  | アルコール消毒液   |    2 | ーー( \_\_\_\_\_\_ )   | ❌不足  | [操作] |  |
|  +--------------------+------+---------------------+--------+--------+  |
|  |                                                 1 / 3 ページ  [>] |  |
|  +-------------------------------------------------------------------+  |
|                                                                         |
+-------------------------------------------------------------------------+
```

* **[操作] ボタン** をクリックすると、その場で「インラインメニュー（入庫 / 出庫 / 棚卸）」がすっとスライド展開し、余計なポップアップすら開かずにその場で数字を入力して完了できるインタラクションにします。

## 3. 主要なビジュアル・グラフィック要素の仕様

### 3.1. 📊 在庫の健康状態（全体ステータスバー）
* **目的：** ユーザーが「今、倉庫内の在庫全体が安全なのか、それとも発注漏れがあるか」をログイン直後に1秒で把握できるようにします。
* **表現：** 円グラフや複雑な折れ線グラフではなく、**1本の統合されたスタックバーグラフ**で表現します。
  * **緑色（良好）：** 適正在庫が保たれている商品の割合（例: 80%）
  * **黄色（警告）：** 残りわずかになり、発注を検討すべき商品の割合（例: 15%）
  * **赤色（不足）：** 在庫が0、または設定された最小在庫を下回っている商品の割合（例: 5%）
* **インタラクション：** バーの各カラー（黄色や赤）をタップすると、その状態の商品だけがテーブルに即座にフィルタリング（自動検索）されます。

### 3.2. 📈 7日間の動き（スパークライン / ミニグラフ）
* **目的：** 単なる「現在の在庫数」だけでなく、「最近急激に減っているのか、それとも安定しているのか」という**時間の流れ（文脈）**をビジュアルで伝えます。
* **表現：** テーブル内に埋め込まれる、極小の折れ線グラフ（スパークライン）。
  * SVGを用いて超軽量に描画（ロード速度を落とさない）。
  * 軸や目盛りはすべて排除し、波線（トレンドライン）のみを表示。
  * 直近で減少傾向が強い場合はラインを赤色（📉）、増加傾向なら緑色（📈）にするなど、色彩的にも直感的に伝えます。

### 3.3. 状態バッジ（良好 / ⚠️警告 / ❌不足）
* **目的：** 各商品の状態をテキストと視覚的シグナルで即座に伝えます。
  * **良好：** 緑色の控えめなテキスト。認知負荷を下げ、意識を向けさせない。
  * **⚠️警告：** 黄色の背景付きバッジ。注意を促す。
  * **❌不足：** 赤色の点滅または目立つバッジ。最優先で入庫アクションが必要であることを示す。

## 4. 操作インタラクション：インライン展開式入力

「入庫」などのボタンを押した際、画面中央に大きなポップアップ（モーダル）を立ち上げると、背景が暗くなりコンテキストが途切れます。これを防ぐため、テーブルの行がその場で縦にすっと広がり、インラインで入力エリアが出現するUIを採用します。

```text
(テーブルの行が縦に広がり、その場で入力欄が出現するイメージ)
+----------------------------------------------------------------------+
| ミネラルウォーター |  120 | 📈 ( ~\_/\_/\_ )    | 良好   | [操作▼]      |
|   +--------------------------------------------------------------+   |
|   |  現在数: 120   [ 入庫 ] [ 出庫 ] [ 棚卸 ]                     |   |
|   |  数量: [ 50  ]  [ 確定する ] [ キャンセル ]                  |   |
|   +--------------------------------------------------------------+   |
+----------------------------------------------------------------------+
```

1. **`[操作]` をクリック：** 行の直下にスムーズなアコーディオンアニメーションで操作パネルが展開。
2. **直感的なキーボード連携：** 展開と同時に数量入力欄にフォーカスが当たり、スマホならテンキーが自動でせり上がる。
3. **`確定する` または `Enter` キー：** API通信が走り、成功するとパネルが閉じて、数量とスパークラインの末尾がその場でスムーズに更新される。

## 5. ミニマリストUX・アクセシビリティ

* ** optimistic UI updates（楽観的UI更新）：**
  通信環境がやや遅い場合でも、確定ボタンを押した瞬間に画面上の数字を一時的に更新し、バックエンドの処理完了を待たずに「完了した心地よさ」をユーザーに感じさせます（APIエラーが返った場合のみ、元の数値に戻して警告を表示）。
* **色のアクセシビリティ：**
  色覚に特性があるユーザーでも、「警告」「不足」の違いが形のアイコン（`⚠️`, `❌`）とバッジのコントラスト比で明確に識別できるように設計します。
