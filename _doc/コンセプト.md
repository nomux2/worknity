# Worknity コンセプト定義書

このドキュメントは、小規模事業者や個人事業主が「認知負荷ゼロ」で直感的に使い続�### ① 「やりたいことがすぐそこにある！」（ゼロディスタンス・アクション）
* **体験の定義:** 画面を開いた瞬間、または数タップ以内に、その時やりたいこと（入庫、出庫、確認など）が目の前に現れる体験。
* **具体策:**
  * **完全スマホファースト（PC不要）:** PCを開く手間やスペースをなくし、すべての操作がスマホ1台で完結する設計にする。
  * **スマホカメラのリーダー化（専用機器不要）:** 高価な専用バーコードリーダーを買わなくても、手持ちのスマホカメラが起動し、その場でJANコードを瞬時に読み取る。
  * **バーコードがなくてもすぐ見つかる:** バーコードがない独自商品や農産物なども、キーボード入力なしで「よく使う商品」や「カテゴリ画像」からワンタップで選択可能にする。
  * メニュー階層を極限まで浅くする（「メニュー ＞ 在庫 ＞ 入出庫 ＞ 登録」ではなく、トップから直接アクション可能に）。

### ② 「迷わない！」（シングルパス・デザイン）
* **体験の定義:** 画面を見ただけで「次に何をすればいいか」が本能的に理解でき、一切の迷いなくタスクを完了できる体験。
* **具体策:**
  * 1画面における主要なアクション（プライマリボタン）を原則1つに絞り込む。
  * 不要なステータス表示や二次的な情報を非表示にし、ノイズを極限まで削る。
  * 入力ミスが起きにくい入力インターフェース（極力キーボード入力を減らし、数字入力はテンキー風の大きなボタンや、`+`/`-` ボタンによる増減を活用）。

### ③ 「難しいことがなくてシンプル！」（コグニティブ・ライト）
* **体験の定義:** 導入時の説明書や事前の研修が一切不要で、プライベートで使っているSNSやメッセージアプリと同じ手軽さで使える体験。
* **具体策:**
  * 専門的なIT用語や業務用語（例：「棚卸」「アロケーション」「マルチテナント」など）をユーザーの目に見える画面からは徹底的に排除する、または極めて直感的な表現に置き換える（「棚卸」→「数を合わせる」、「入庫」→「棚に入れる」など）。
  * 「初期設定」「マスタ登録」といった事前の面倒な準備を不要にし、使いながらデータが自然に整う仕組みにする。
  * 料金や機能のON/OFFも、スマホのアプリストアのように「1クリックで開始/いつでも1秒で停止」できる安心感を提供する。

## 2. 具体的な体験シナリオ（ユースケース）

コンセプトを具現化する具体的な画面設計・フローの例です。

### シナリオ1：未登録商品のJANコードスキャンから即時登録・入庫（スマホカメラ使用）
* **一般的なシステムの場合（高い認知負荷）:**
  1. 「入庫画面」でJANコードをスキャンする。
  2. 「商品マスタに存在しません」とエラーが出て作業が中断される。
  3. 入庫画面を一度閉じ、「商品マスタ管理画面」へ移動する。
  4. 「新規登録」を押し、バーコード番号や商品名を入力して保存する。
  5. 再び「入庫画面」を開き、バーコードをスキャンし直す。
  6. 数量を入力してやっと入庫が完了する。
  * ❌ **問題点:** 画面遷移が多く、作業がブツブツと途切れて迷いやすい。
* **Worknityの体験（インサイド・フロー：作業を中断させない）:**
  1. **スマホのカメラ**でJANコードをスキャンする。
  2. 未登録の場合でもエラーにせず、バックエンドで**無料API（Yahoo!/楽天等の商品検索API）**を裏側で叩いて商品名を検索する。
  3. **自動引き当てに成功した場合:**
     * その画面のまま、**「[自動取得した商品名]」**が入力された状態で「登録して入庫しますか？」と表示される。ユーザーは内容を確認して決定ボタンを押すだけ。
  4. **自動引き当てに失敗した場合（独自商品など）:**
     * その画面のまま、「新しい商品です。商品名を入力してください」と空の入力フィールドを表示し、手入力を促す。
  * ⭕ **メリット:** 画面遷移はゼロ。ほとんどの既存商品であれば、ユーザーは「スキャンして決定」の最小アクションだけで商品登録と入庫を完了できる。

### シナリオ2：バーコードがない商品のクイック入出庫（ノンコード・アシスト）
* **一般的なシステムの場合（高い認知負荷）:**
  1. 検索窓にキーボードで「トマト」と入力して検索する。
  2. たくさん出てくる検索結果（トマトMサイズ、トマトLサイズなど）から選ぶ。
  3. 選択後、別の画面に遷移して数量を入力する。
* **Worknityの体験（タップのみ・ノンキーボード）:**
  1. 「バーコードなし商品を追加」をタップする。
  2. 画面に登録済みのバーコードなし商品が「画像（または色のついた四角形）と大きなテキスト」のカード形式で一覧表示される。
  3. 該当する商品のカードをタップすると、その場で「数量: `+` `1` `-`」という調節ポップアップが出る。
  4. `+`を数回タップするかスライダーで数量を調整し、「決定」を押すだけで完了する。
  * ⭕ **メリット:** キーボードを一切開くことなく、片手親指のタップ操作だけで入出庫が完了する。

## 3. 議論したいテーマと問い

このコンセプトをより強固にし、具体的な機能や画面設計に落とし込むために、以下の点についてディスカッションを進めたいと考えています。

1. **「やりたいことがすぐそこにある」の最優先アクションは？**
   * 初期フェーズの「在庫管理」において、ユーザーが最も頻繁に行う「やりたいこと」の主役は何でしょうか？（例：バーコード読み取りでの入出庫、品名検索からの数量変更、あるいは現状の在庫一覧の確認？）
2. **「難しいことなし」を実現するための「設定」のあり方**
   * 一般的な業務アプリにあるような「マスタ登録（商品登録）」や「組織設定」をどうやって「意識させずに」完了させるか？（例：最初からダミーデータがあってそれを上書きするだけで使える、最初の入庫時に入力した品名が自動でマスタになる、など）
3. **ユーザー像の具体化（どんなシーンで、誰が使うか？）**
   * このシンプルさを最も喜んでくれるユーザーは、どのような環境でこのアプリを開きますか？（例：片手に荷物を持った倉庫の中、店頭での接客の合間、移動中の車内など）
