# システム要件定義書

本書は、ミニマリスト業務管理システム「Worknity（フェーズ1）」におけるシステム要件、技術スタック、および実装仕様を定義するポータル・インデックスドキュメントである。

各システム要件の詳細は、それぞれの個別要件ドキュメントを参照すること。開発者はこれらのドキュメントおよび [要件定義書.md](file:///d:/myApp/worknity/doc/要件定義書.md) をもとに実装を行う。

---

## 各システム要件の詳細

### 1. [システムアーキテクチャ・技術スタック](file:///d:/myApp/worknity/doc/システム要件/1_システムアーキテクチャ.md)
* **概要：** Xserverを利用した初期インフラ構成、モノレポ構成によるフロントエンド（React/SPA）とバックエンド（Laravel/API）の領域分離、および将来的なインフラ拡張・AI連携（MCP）のための「仕込み」設計について定義。

### 2. [データベース要件](file:///d:/myApp/worknity/doc/システム要件/2_データベース要件.md)
* **概要：** MySQL/MariaDBの基本設定（照合順序 `utf8mb4_bin` など）、マルチテナント環境下におけるデータの徹底的な分離・ガード（`company_id` による自動フィルタリング）、インデックス設計原則、および将来の特化型拡張に対応する JSON型（`attributes`）の運用ガイドライン。
* **関連資料：** 詳細なスキーマ設計は [データベース設計書.md](file:///d:/myApp/worknity/doc/データベース設計書.md) を参照。

### 3. [機能的システム要件](file:///d:/myApp/worknity/doc/システム要件/3_機能要件.md)
* **概要：** JWT（JSON Web Token）を用いたステートレスなマルチテナント認証、管理者（admin）によるスタッフアカウント追加仕様、在庫管理（入出庫・棚卸）におけるトランザクション制御（レースコンディション対策）、およびAI（MCP）連携エンドポイントの定義とHuman-in-the-loop（実行確認UI）による安全性担保の仕組み。

### 4. [非機能要件・UX原則](file:///d:/myApp/worknity/doc/システム要件/4_非機能要件.md)
* **概要：** 認知負荷をゼロにするミニマリストUI/UX設計（ログイン後即操作、初期設定ステップの排除）、将来のアドオン機能トグル管理、いつでも1秒で無効化（解約）できる精神的負担のない契約コントロール、SSL/TLS通信、SQLインジェクション/XSS脆弱性対策、およびバックアップ・コード品質基準。
