# MCP＆AI連携開発ルール (MCP & AI Integration Rules)

AIエージェントによるシステム自動操作（Model Context Protocol経由）を、安全かつ確実に制御するためのルールを定義します。

---

## 1. Human-in-the-loop（実行承認）の強制
* **ルールの要旨**: AIエージェントの誤操作や暴走によるデータベース破壊・意図しない在庫変更を防ぐため、最終決定は必ず人間が行う。
* **具体的アクション**:
  1. AIが `/mcp/v1/tools/call` を要求した際、バックエンドが直接DBを即時更新してはならない。
  2. 代わりに、フロントエンド上に「AIによる在庫更新要求：[商品名] を [数量] 個 [入庫/出庫/棚卸] しますか？」という**明示的な確認モーダル（承認ダイアログ）**を表示する。
  3. 人間のオペレーターが「承認（クリック）」を押したことをトリガーとして、初めてAPIがデータベースの更新を確定する、または承認トークンを付与してリクエストを完了させるフローを設計する。

## 2. MCPエンドポイントの物理的・論理的分離
* **ルールの要旨**: AIエージェント用のAPIと、通常のフロントエンドSPA用のAPIを混同させず、アクセス制御を明確にする。
* **具体的アクション**:
  1. AI用のエンドポイントは `/mcp/v1/...` プレフィックスを使用し、一般フロントエンド用（`/api/v1/...`）と完全にルートレベルで分離する。
  2. AI向けに提供するリソース一覧（`/mcp/v1/resources/list` 等）は、個人情報（顧客情報、スタッフ情報など）を含めず、**「安全にフィルタリングされた在庫のサマリー情報」**のみに制限すること。
  3. 各ツールのスキーマ定義（`/mcp/v1/tools/list`）は、AIが解釈しやすいように明確な JSON Schema 形式で返却し、かつ引数のバリデーションルールを厳密に定義する。

## 3. テナントガードの継承
* **ルールの要旨**: AIからの呼び出しであっても、マルチテナントの壁を決して越えさせない。
* **具体的アクション**:
  1. AIエージェント経由のMCPリクエストであっても、認証されたユーザー（トークン）が属する `company_id` の範囲内でのみデータアクセスを許可する。
  2. MCPコントローラー内でも、通常のEloquentモデルを使用し、グローバルスコープ（`company_id` による自動絞り込み）が確実に機能していることをテストコード等で保証する。
  3. AIがプロンプトインジェクション等によって他テナントの情報を要求した場合、該当データが存在しないかのように振る舞う（404エラーを返す）。
