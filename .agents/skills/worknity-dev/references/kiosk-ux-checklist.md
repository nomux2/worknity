# キオスクモードUI ＆ PCに詳しくない利用者向けUXチェックリスト

Worknity の画面を追加・修正する際は、**「PCやITに詳しくない現場スタッフ・店舗オーナー・客席のお客様が、説明書なしで直感的に迷わず使えるか」** を基準に、以下の項目を必ず検証してください。

---

## 1. キオスクモード・レイアウト原則

- [ ] **全画面 `100vh` 固定（縦スクロール排除）**
  - 画面全体の外側コンテナが `100vh` に収まり、ブラウザ全体の縦スクロールが発生しない構造（`overflow: hidden`）になっているか？
  - テーブルやリスト等の大量データは、カード・ペイン内のインナースクロール（`overflow-y: auto`、`.table-responsive` 等）で制御されているか？
- [ ] **ゼロ・コンテキストスイッチ（画面遷移の排除）**
  - 「一覧画面 ➔ 詳細画面 ➔ 編集画面 ➔ 確認画面」のような多段階ページ遷移を行っていないか？
  - 2ペイン構造（左ペイン：アクション、右ペイン：一覧）やインライン展開、モーダル等で、現在の作業文脈を失わずにその場で完結できるか？
- [ ] **顧客・現場用キオスクロック仕様（該当画面のみ）**
  - 客席・店頭設置端末モード（`/catalog` 等）では、管理者用ヘッダーや他機能へのナビゲーションが完全に非表示になっているか？
  - 通常画面への復帰には、必ずテンキー入力式のパスワード認証（`KioskUnlockModal`）を経由しているか？

---

## 2. PCに詳しくない人でも迷わない「究極のシンプルUX」

- [ ] **専門用語・IT用語の完全排除**
  - 画面上の見出し・ボタン・プレースホルダー・エラーメッセージに、以下のような専門用語が含まれていないか？
    - ❌ 避けるべき言葉：`マスタ`、`トランザクション`、`アロケーション`、`レコード`、`バリデーションエラー`、`マルチテナント`、`パラメータ`、`キャッシュ`、`棚卸`（一般向け画面）
    - ⭕ 直感的な言い換え：`登録リスト` / `よく使う項目`、`履歴`、`数を合わせる`、`棚に入れる（入庫）`、`棚から出す（出庫）`、`入力内容を確認してください`
- [ ] **キーボード入力を極限まで減らす（タッチ・ワンタップ完結）**
  - 数字入力には、キーボードを叩かせるのではなく **`+` / `-` 増減ボタン** や **画面上の大きなテンキーUI**、`components/ui/NumberInput.tsx` を提供しているか？
  - 選択肢は自由記述させず、ボタン選択、`Select` / `Combobox`、または「よく使う項目」からのワンタップ選択にしているか？
- [ ] **シングルパス・デザイン（1画面1プライマリアクション）**
  - 画面を開いた瞬間に「次にどのボタンを押せばよいか」が1秒でわかるか？
  - 同じ画面内に目立つプライマリボタンが複数乱立していないか？（主要な決定アクションは1つに絞り、補助アクションは控えめなスタイルにする）
- [ ] **タップ領域の確保と押し間違い防止**
  - すべてのボタン、タブ、切り替えスイッチ、テーブル操作アイコンのタップ領域（高さ・幅）が **最小 `44px × 44px` 以上**（推奨 `48px`）確保されているか？
  - 隣り合うボタン同士に十分な余白（`8px〜12px` 以上）があり、指での誤タップを防げているか？
- [ ] **即時フィードバックと安心感（楽観的UI + わかりやすいエラー）**
  - ボタンを押した瞬間に反応（マイクロアニメーション、状態変化、二重押し防止のローディング表示）があるか？
  - 通信エラー時は自動的に元の表示へロールバックし、「何が起きたか・どうすればよいか」が専門用語なしで伝わる通知を出しているか？
