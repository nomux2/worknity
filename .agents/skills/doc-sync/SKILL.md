# Worknity 設計書同期・整合性管理スキル (`doc-sync`)

Worknity の一般開発ルール「設計書ファーストの徹底」に基づき、コードを修正する前に設計書を確認・更新し、ドキュメントと実装の乖離（ドリフト）をゼロに保つためのスキルです。

---

## 1. いつこのスキルを使うか

1. **APIエンドポイントやリクエスト/レスポンス形式を追加・変更する時**
2. **データベースのテーブル・カラム・マイグレーションを追加・変更する時**
3. **画面レイアウト（キオスクUI）、画面遷移、機能仕様を変更する時**
4. **既存コードと設計書の間に矛盾・乖離が見つかった時**

---

## 2. Worknity 設計書マップ（`_doc/`）

変更対象に応じて、以下のどの設計書を更新すべきかを特定してください。

| 変更カテゴリ | 対象ドキュメントパス | 記載・確認すべき内容 |
| :--- | :--- | :--- |
| **全体構成・共通仕様** | `_doc/基本設計書.md`<br>`_doc/要件定義書.md`<br>`_doc/コンセプト.md` | システム構成、全画面キオスクスタイル、共通ヘッダー、認証方針 |
| **システム・非機能要件** | `_doc/システム要件/1_システムアーキテクチャ.md`<br>`_doc/システム要件/2_データベース要件.md`<br>`_doc/システム要件/3_機能要件.md`<br>`_doc/システム要件/4_非機能要件.md`<br>`_doc/システム要件/5_多言語対応.md`<br>`_doc/システム要件/6_ロール・権限設計.md` | インフラ、マルチテナント分離、RBAC権限マトリクス、多言語化ルール |
| **API仕様** | `_doc/API定義書.md` | エンドポイントURL、HTTPメソッド、認証要否、リクエストパラメータ、レスポンスJSON構造、ステータスコード（404/422等） |
| **DB全体スキーマ** | `_doc/データベース設計書.md` | ER図（Mermaid）、テーブル一覧、カラム定義、複合インデックス定義 |
| **個別モジュール仕様** | `_doc/機能/<機能名>/機能仕様.md`<br>`_doc/機能/<機能名>/画面設計.md`<br>`_doc/機能/<機能名>/データベース設計.md` | 各機能（在庫管理、カタログ機能、発注管理、申請報告管理、タスク管理、プロジェクト管理、顧客管理、勤怠管理、マスタ管理、ユーザー管理、ホーム、ログイン、ヘッダー機能）の詳細仕様 |

## 3. 設計書同期の手順（ワークフロー）

### Step 1: 乖離・影響範囲の特定
1. ユーザーの要望または修正対象のコード（`backend/routes/api.php`、`backend/database/migrations/`、`apps/main-app/src/`）を確認する。
2. 対応する `_doc/` 内のファイルを読み込み、現在の記述内容を確認する。
   - **注意（テナントIDの命名整合性）**: 初期ドキュメントの一部では `company_id` と表記され、実装および機能別DB設計書では `organization_id` が使用されている箇所がある。新規記述・修正時は実際のテーブル構造（`organization_id`）と正確に一致させること。

### Step 2: ユーザーへの確認と合意（`/grill-me` 連携）
- 既存の設計書と異なる仕様へ変更する場合、**コードを先に書き換えてはならない**。
- 「どの設計書の、どの仕様を、どのように変更するか」を明確にし、判断が必要な点は `ask_question` ツールで1問ずつ確認して合意を得る。

### Step 3: 設計書の先行更新
1. 合意した仕様に基づき、該当する `_doc/` 配下の Markdown ファイルを先に更新する。
   - **UI/画面設計の更新時**: キオスクモード原則（`100vh` 固定、縦スクロール排除、タップ領域 `44px` 以上、PCに詳しくない人向けの平易な用語）が画面設計書にも反映されていることを確認する。
   - **DB設計の更新時**: `_doc/機能/<機能名>/データベース設計.md` だけでなく、必要に応じて `_doc/データベース設計書.md` も同期する。
   - **APIの更新時**: `_doc/API定義書.md` のリクエスト/レスポンス例とエラーコードを最新化する。

### Step 4: テスト＆コード実装への引き継ぎ
- 設計書の更新が完了したら、`worknity-dev` スキルの Step 3（テストファースト実装）へ進み、更新した設計書通りにテストと実装を行う。
